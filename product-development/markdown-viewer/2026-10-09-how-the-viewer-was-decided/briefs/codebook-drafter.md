# Codebook drafter

Read `briefs/standing-brief-block.md` first, then `briefs/venue-situation.md`, then `/usr/local/src/aesop/pmf-sage/sage-S-survey.md`, then `/usr/local/src/aesop/pmf-sage/INVARIANTS.md`, then `3-decisions/questions.md` and `0-comparables/shape-note.md`. Nothing else in the repository is open to you. You have seen no frame and no product page, and avoid looking for one, since the codebook is drafted blind and frozen before collection.

Write `0-comparables/codebook-v1.md`: the coding manual a Sonnet-tier coding clerk applies to a verbatim profile of one comparable product (the text its own pages publish, captured with URLs and dates) to fill one row of the coded corpus. The products are applications, extensions or terminal programs a person installs or opens to read or write markdown files, on any platform, found through stores, package repositories and repository topic lists.

The codebook carries, at least:

- a variable for whom the product sells to, coded from what the product publishes with "not stated" as a value, whose values are the buyer classes the situation paragraph lists, several allowed per product, and nothing coded from the product's features (a feature is not an audience);
- the parameters `3-decisions/questions.md` asks, each as a variable with a closed value set drawn from how such products could answer it, "not stated" always among the values;
- the four dimensions of the shape note as variables;
- a variable for whether the product is a reader only or also an editor; one for the product kind (desktop application, browser extension, editor extension, terminal program, mobile application, component, service); one for platforms; one for the price with its shape as stated and the licence; one for the surface the product sells on; one for the unit a buyer takes; one for the distribution channels named; one for the markdown forms the page claims to render; one for whether files stay local; one for the last release date and whether the project is archived; one for any AI-related claim; one for the sentence the page gives on why the product exists, captured verbatim;
- an eligibility variable, applied first, with the rule stated so two coding clerks apply it alike.

Standing instructions to write into the manual: text only; silence is a value, not a fact; no inference in either direction; a rule two coding clerks would apply differently has failed, so every variable carries a decision rule and at least one worked example of a hard case written from imagination, not from any real product; a coding clerk who meets a case the rule cannot decide codes "undecidable" and notes it, and never extends the rule. Changing a frozen rule takes a version, a date and re-coding of everything coded.

Mark the codebook frozen at the end with the date. Your final message states the number of variables, the ones you expect to be hardest to code reliably, and why.
