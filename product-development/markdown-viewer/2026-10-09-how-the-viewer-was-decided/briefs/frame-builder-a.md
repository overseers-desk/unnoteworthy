# Frame builder A: the lists programmers use

Read `briefs/standing-brief-block.md` first, then `briefs/venue-situation.md`, then `/usr/local/src/aesop/pmf-sage/sage-S-survey.md` section 1 steps 2 and 3, then `/usr/local/src/aesop/pmf-sage/INVARIANTS.md` rule I6, then `0-comparables/shape-note.md`. Nothing else in the repository is open to you.

A frame is populated from published lists that can be re-opened and counted, standing for the market buyers choose from. Your lists, each named under the strike-list row that admits its buyer:

1. **Homebrew**, the formulae and casks whose description contains "markdown": the catalogue at https://formulae.brew.sh/api/formula.json and https://formulae.brew.sh/api/cask.json, with 30-day, 90-day and 365-day install counts from https://formulae.brew.sh/api/analytics/install/{30d,90d,365d}.json and the cask equivalents at /api/analytics/cask-install/. Admits developers and coders (RULED strike-list:developers-and-coders), and through the casks the writers and note-takers on a Mac.
2. **Debian**, every package `apt-cache search markdown` returns on the host running this brief (record its distribution release from `/etc/os-release`, which pins the provenance). Admits developers and coders (RULED strike-list:developers-and-coders) and terminal readers (RULED strike-list:terminal-readers).
3. **GitHub topics** `markdown-viewer`, `markdown-editor`, `markdown-preview` and `markdown-reader`, every repository with 200 stars or more, through `gh api 'search/repositories?q=topic:<topic>+stars:>=200&sort=stars&per_page=100'` with paging; record each topic's total count with and without the star floor. The floor is the mechanical rule; state it. Admits developers and coders (RULED strike-list:developers-and-coders), terminal readers (RULED strike-list:terminal-readers) and application developers embedding a markdown view (RULED strike-list:application-developers-embedding-a-markdown-view).

Eligibility, applied to every entry and recorded with the reason: an entry is in when it is an application, extension or terminal program a person installs or opens to read or write markdown files. Out: libraries and parsers, converters and linters, static-site generators, language servers, themes, fonts, documentation packages, and services that read no markdown file. Where the entry's own description cannot settle it, keep it as "undecidable" for the frame review rather than deciding by name.

Write one TSV per list under `0-comparables/frame/`: `homebrew.tsv`, `debian.tsv`, `github-topics.tsv`, with columns: list, cell (formula or cask; topic name), entry, identifier or URL, the list's own count for the entry (installs over each window, stars), description as the list gives it, eligible (in, out, undecidable), reason. Write one coverage note per list beside it, `<list>-coverage.md`: who runs the list, how many entries it held when you opened it, the date, who is structurally shut out of it, every step from list size to frame size with its count, and whether the cell ends as a census or a sample under which rule.

Your final message gives, per list, the counts list to eligible, what surprised you against what you expected, and what you could not reach.
