A frame is populated from published lists that can be re-opened and counted, standing for the market buyers choose from. Your lists, each named under the strike-list row that admits its buyer:

1. **The VS Code Marketplace**, through `POST https://marketplace.visualstudio.com/_apis/public/gallery/extensionquery` with headers `Content-Type: application/json` and `Accept: application/json;api-version=3.0-preview.1` and body `{"filters":[{"criteria":[{"filterType":8,"value":"Microsoft.VisualStudio.Code"},{"filterType":10,"value":"markdown"}],"pageNumber":1,"pageSize":100,"sortBy":4,"sortOrder":0}],"flags":914}`, which sorts by installs. Record the total count the response gives, take the first 100 as the cell under that stated rule, and keep name, publisher, install count, rating count, short description, last updated. Admits developers and coders (RULED strike-list:developers-and-coders).
2. **The Chrome Web Store**, the search page for "markdown viewer" at https://chromewebstore.google.com/search/markdown%20viewer and for "markdown" ; where the page is script-rendered to a plain fetch, use the serialised-browsing skill if available, and if the store cannot be enumerated record that as the coverage note's finding rather than substituting a search. Keep each listing's name, user count, rating and description. Admits plain readers of received markdown files (RULED strike-list:plain-readers-of-received-markdown-files).
3. **AlternativeTo**, the lists of alternatives to Typora, to Obsidian, to Marked 2 and to Glow, as far as a fetch can page them; record how many each list claims and how many you could read. Admits writers and authors (RULED strike-list:writers-and-authors), note-takers and personal knowledge managers (RULED strike-list:note-takers-and-personal-knowledge-managers) and terminal readers (RULED strike-list:terminal-readers).
4. **The curated list awesome-claude-code** on GitHub (hesreallyhim/awesome-claude-code), every entry whose description says it views, reads, browses or renders transcripts, sessions, logs or markdown. Admits readers of what AI agents write (RULED strike-list:readers-of-what-ai-agents-write). Where the list holds no such entry, that is the finding.
5. **The Tcl wiki's Markdown page**, https://wiki.tcl-lang.org/page/Markdown, and the tklib and teatotal module indexes, every entry that renders markdown in Tk or parses it in Tcl. Admits application developers embedding a markdown view (RULED strike-list:application-developers-embedding-a-markdown-view).

Eligibility, applied to every entry and recorded with the reason: in when it is an application, extension or component a person installs or opens to read or write markdown files, or builds into a program to do so. Out: converters, linters, themes, snippets, and extensions whose markdown support is incidental to another purpose. Where the description cannot settle it, keep it as "undecidable" for the frame review.

Write one TSV per list under `0-comparables/frame/`: `vscode.tsv`, `chrome-web-store.tsv`, `alternativeto.tsv`, `awesome-claude-code.tsv`, `tcl.tsv`, with columns: list, entry, identifier or URL, the list's own counts for the entry, description as the list gives it, eligible (in, out, undecidable), reason. Write one coverage note per list beside it, `<list>-coverage.md`: who runs the list, how many entries it held when you opened it, the date, who is structurally shut out, every step from list size to frame size with its count, and census or sample under which rule.

Your final message gives, per list, the counts list to eligible, what surprised you against what you expected, and what you could not reach.
