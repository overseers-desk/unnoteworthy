# Frame reviewer: the adversarial read before collection

Read `briefs/standing-brief-block.md` first, then `briefs/venue-situation.md`, then `/usr/local/src/aesop/pmf-sage/sage-S-survey.md` section 1 steps 2, 3 and 5, then `/usr/local/src/aesop/pmf-sage/INVARIANTS.md`, then `0-comparables/shape-note.md`, then every file under `0-comparables/frame/`: the per-list TSVs, their coverage notes, and `frame.tsv` with `frame-cells.md`, the merged frame and its cell counts. Nothing else in the repository is open to you, and no product page: you judge the enumerations, not the products.

Attack the frame as a set of enumerations. For each cell (one source list, or one sub-list such as a single GitHub topic or the formulae against the casks of one package manager), ask:

- Is it a proxy population: does the list enumerate the market a buyer chooses from, or something else that happens to be countable (what a maker chose to publish there, what carries a word in its description, what a crowd liked)? Name what the list structurally shuts out.
- Is it quota-shaped: did a cap (a star floor, a page size, the first hundred by installs) draw the cell, and does the coverage note state the cap as a mechanical rule with the uncapped count beside it?
- Is a sample dressed as a census, or a census dressed as a sample?
- Are cross-cell comparisons forbidden because the list's architecture is confounded with the dimension compared (a store that lists only free apps against one that lists paid; a list ranked by installs against one ranked by likes)? Say which comparisons the findings may not make.
- Do the eligibility calls hold: is the rule stated so two clerks would apply it alike, are the "undecidable" rows few enough to resolve by a second read, and does any "out" row look like a product a buyer would weigh?
- Are the duplicates across lists resolved (a product sitting in several cells is a single comparable with several memberships), and are the flagged possible duplicates in `frame-cells.md` real?
- Does each cell carry the shape note's four dimensions, so a rate measured in it can be marked shared or differs against the operator?

Status marks (store verification, badges, awards) weigh as buyers weigh them; strike any eligibility or cell rule that uses one without a buyer-evidence leg.

Give a verdict per cell: go, conditional (with the condition stated so a collector can obey it), or no-go (with the reason). Write `0-comparables/frame-review.md`: the verdicts in a table, the forbidden comparisons, the duplicate resolutions you order, the undecidable rows you resolve and the rule you resolved them by, and the counts of the frame as collection may use it. Collection runs only on cells that pass, under their conditions. Your final message is the verdict table and the count collection will run on.
